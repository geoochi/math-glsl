# Prompt

生成 `mandelbrot.mp4` 用的 prompt。可以直接丢给 AI agent，也可以自己照着改。

---

> 用 math-glsl 渲染一段视频。
>
> **画面**：不要坐标系，满屏都是曼德博集合。镜头从能看见整朵集合（心形主体 + 左侧圆球）的位置出发，
> 沿一条预设路线朝着 `-0.7436438870371587 + 0.13182590420531197i` 这个点无限推近，
> 途中不断有新结构从边界里长出来。推进速度必须是**指数式**的——视野高度按 `exp` 衰减，
> 这样每一秒看到的形变速率都一样；线性推近会前松后紧，后段快得看不清。
> 前 22% 的时长用来把中心平移到目标点，之后中心不动，只收缩视野。
>
> **上色**：用平滑逃逸时间（不是整数迭代数，否则会有硬色带），色相随逃逸时间循环、
> 并随时间缓慢流动；集合内部接近纯黑偏深蓝；集合边界要有一条**恒定 1 像素宽**的蓝色辉光，
> 无论缩放到多深都不能变粗。
>
> **规格**：3840×2160，60fps，10bit，时长 12 秒。

---

## 复现

```bash
git clone https://github.com/geoochi/math-glsl && cd math-glsl
make
# HWENC=0：和仓库里的 wave 演示一样用软件 H.264 编，兼容性最好，任何播放器都能直接打开。
HWENC=0 SHADER=demo/mandelbrot/mandelbrot.glsl \
    ./render_glsl demo/mandelbrot/mandelbrot.mp4 3840 2160 60 12
```

## 这个 prompt 是怎么落到代码上的

1. **平滑逃逸时间**：整数迭代数会让相邻像素的差值跳变，画出同心硬色带。标准修正是
   `mu = n + 1 - log2(log|z| / log2)`，把离散计数变成连续量。
2. **指数缩放**：视野半高 `H = exp(mix(log(H0), log(H1), t/T))`。在对数空间插值 =
   在真实空间里等比缩放，观感上就是恒定推近速度。
3. **中心先飞后停**：`smoothstep` 控前 22% 把中心从 `(-0.5, 0)` 移到目标点，
   之后只收缩视野。`TARGET` 的 16 位小数必须保留，截短了深缩放阶段目标点会漂出画面。
4. **1 像素辉光**：`fwidth(mu)` 在集合边界处爆炸，用 `clamp((fwidth(mu)-3)/12, 0, 1)`
   就能得到一条与缩放深度无关的细线。这是着色器路线的相对优势——换成 `cv2` 就得额外做一遍模糊。
5. **迭代上限随深度提高**：`cap = mix(220, 520, u)`。深缩放时边界附近的点逃逸得很慢，
   上限不够就会把本属于外部的点判成"内部"，细节糊成一团黑。
6. **精度边界**：float 大约能推近 4–5 个数量级，这里刻意止步于 ~5000 倍（半高 `3e-4`）。
   想再深需要把参考轨道预计算成常量数组做扰动法，那是另一个量级的工程量。

## 可调参数

| 常量 | 作用 |
|---|---|
| `TARGET` | 推近终点，换成别的边界点就是完全不同的片子 |
| `HALF_0` / `HALF_1` | 起点视野半高 / 终点视野半高，比值即总缩放倍数 |
| `ROT_TOTAL` | 整个片子的镜头滚转（弧度），默认 0；给个 0.3 会更有"手持感" |
| `PAL_SPEED` | 色相流动速度，设 0 则配色完全静止 |
| `PAL_SCALE` | 每单位逃逸时间经过多少色相循环，越大色带越密 |

## 竖屏（9:16）

```bash
SHADER=demo/mandelbrot/mandelbrot.glsl \
    ./render_glsl demo/mandelbrot/mandelbrot_portrait_4k10bit.mp4 2160 3840 60 12
```

**同一个着色器不用改。** 视野按 `res.y` 归一化，所以竖屏只是横向窗口变窄：
t = 0 时看到 `x ∈ [-1.32, 0.32]`、`y ∈ [-1.45, 1.45]`，而集合主体是
`x ∈ [-1.25, 0.25]`、`y ∈ [-1.15, 1.15]`——**主体刚好铺满画面宽度、不会被裁**，
只有最左边那根细天线出画。想让主体四周留更多余量，把 `HALF_0` 提到 1.6 左右即可。

| 文件 | 说明 |
|---|---|
| `mandelbrot_portrait_4k10bit.mp4` | 2160×3840 60fps 10bit HEVC，竖屏母版 |
| `mandelbrot_portrait_x1080p30.mp4` | 1080×1920 30fps 8bit H.264，43 MB，可直接发 X |

注意 X 的帮助页写竖屏上限是 1200×1900，而 1080×1920 比它高 20 像素。实际平台上 1080×1920
是竖屏通行的标准尺寸，上传正常；真要严格卡文档就压到 1080×1900。
